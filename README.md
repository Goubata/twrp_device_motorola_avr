# TWRP device tree for motorola avr (XT2611)

| | |
|---|---|
| SoC | Qualcomm SM8845 (canoe) |
| Android | 16 (W3WW36.65-25-3-4, security patch 2026-06-01) |
| Recovery | dedicated `recovery_a/_b`, boot header v4, ramdisk only (kernel from `boot`) |
| Storage | UFS, F2FS `/data` with FBE v2 + metadata encryption (hardware-wrapped keys) |
| Display | 1440x3168, 520 dpi, center punch hole |
| Touch | Goodix THP (`goodix_brl_thp.ko` + `odm_tsc`) |

Built from [TWRP-Test/platform_manifest_twrp_aosp](https://github.com/TWRP-Test/platform_manifest_twrp_aosp)
`twrp-16.0` with GitHub Actions (`.github/workflows/build.yml`).
Structure follows [TWRP-Test/twrp_device_xiaomi_sm8850](https://github.com/TWRP-Test/twrp_device_xiaomi_sm8850) (Apache-2.0).

## Layout

- `BoardConfig.mk`, `device.mk`, `twrp_avr.mk`: build configuration
- `recovery.fstab`, `recovery/root/system/etc/twrp.flags`: partitions
- `recovery/root/`: hand-written init scripts and helpers
- `prebuilt/root/`: vendor blobs, generated by `extract-files.py` from a dump of the
  device according to `proprietary-files.txt` (NEEDED dependencies are added
  automatically; `system-deps.txt` lists what must come from TWRP itself)
- `scripts/finalize-recovery.py`: run by CI after the build; verifies the ramdisk and
  repacks the image exactly like the stock `recovery_a` (no image is produced if a
  check fails)

## KeyMint and the system patch level (important)

QTI KeyMint binds key blobs to the OS version and patch levels it is told about.
This recovery reports the values of the installed system (`AVR_OS_VERSION`,
`AVR_OS_PATCH`, `AVR_VENDOR_PATCH` in `BoardConfig.mk`), not TWRP's usual
`99.87.36` / `2099-12-31`. After every OTA, update them from the device and rebuild:

```sh
adb shell getprop ro.build.version.release
adb shell getprop ro.build.version.security_patch
adb shell getprop ro.vendor.build.security_patch
```

If they no longer match, `resyncapex.sh` stops KeyMint before decryption (decryption
fails, nothing is written) and logs the values to use.

## Flashing

`fastboot boot` is not supported for this ramdisk-only image. Flash the current slot
and keep the stock image to roll back:

```sh
fastboot getvar current-slot
fastboot flash recovery_a twrp-avr-recovery.img
fastboot reboot recovery
# roll back:
fastboot flash recovery_a recovery_a-stock.img
```
